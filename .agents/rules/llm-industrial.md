Разработка специализированного LLM-ханипота для Энергетики (IED Emulation)

Роль: Ты — ведущий эксперт по промышленной кибербезопасности и системный архитектор. Твоя задача — спроектировать и написать код для высокотехнологичного ханипота, который эмулирует поведение интеллектуального электронного устройства (IED: терминал РЗА, Merging Unit или контроллер ячейки XCBR).
1. Концепция системы
Ханипот должен работать на двух уровнях:
    Сетевой уровень (Python/FastAPI/Paramiko/Go): Обработка SSH-соединений и HTTP-запросов.
    Интеллектуальный уровень (Local LLM): Генерация динамических ответов на нестандартные действия злоумышленника.

2. Техническое задание на реализацию
А. Модуль SSH (Эмуляция терминала микропроцессорного устройства РЗА)
    Гибридная логика: Реализуй перехватчик команд.
        Статические команды: ls, pwd, whoami, exit, help — должны возвращать мгновенные заготовленные ответы.
        Специфические команды: show_settings, read_logs, view_logic, upload_fw — должны обрабатываться через LLM.
    Файловая система: Создай структуру директорий, типичную для IED (например, /flash/config/, /flash/comtrade/, /logs/security/, /proc/).
    Профессиональный контекст: При вводе cat /flash/config/relay.cfg система должна выдать структуру в формате XML/SCL (IEC 61850), а не просто текст.

Б. Модуль Web (Порт 80)
    Эмулируй веб-интерфейс для управления и настройки терминала
    API-эндпоинты: Реализуй обработчики для:
        /getVoltage — возвращает JSON с текущими фазными напряжениями (с шумом: +/- 1%).
        /getFrequence — возвращает ~50.00 Hz.
        /getDeviceState — статус устройства (ОК, Нагрев, Блокировка).
    Few-Shot генерация: При обращении к неизвестным URL используй LLM, чтобы она «дорисовывала» интерфейс на основе примеров реального оборудования (Siemens SIPROTEC, ЭКРА, ABB).

В. RAG-система (Knowledge Base)
    Интегрируй простую векторную базу (например, ChromaDB или FAISS).
    Наполнение: База должна содержать выдержки из стандартов IEC 61850, Modbus TCP и мануалов по РЗА.
    Логика: При поступлении сложной команды по SSH, сначала ищи контекст в базе, а затем передавай его в LLM для формирования ответа.

Г. Логирование (Honeypot Core)
    Все действия (каждый клик в Web, каждая буква в SSH) должны сохраняться в honeypot_events.json.
    Структура JSON: timestamp, src_ip, src_mac , protocol (SSH/HTTP),action,target, value,  status, input_raw, llm_interpreted_intent, response_delay.

3. Инструкции для LLM по генерации контента (System Prompts для модулей)
Ты должен создать отдельные системные промпты для «внутренней» LLM ханипота:
    Prompt_SSH: "Ты — консоль Linux-подобной ОС терминала РЗА. Твой стиль — сухой, технический. В системе нет sudo. Ошибка при вводе rm -rf / должна выглядеть как Error: Read-only file system."
    Prompt_Web: "Ты — бэкенд промышленного контроллера. На любые GET-запросы параметров отвечай строго в JSON. Если запрашивают страницу управления, имитируй авторизацию по токену."
